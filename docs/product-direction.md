# 产品方向

## 一句话定义

一个运行在个人本地机器上、通过外部设备插件交互、底层复用 Codex 的个人 Supervisor 助手运行时。

## 目标用户

第一目标用户是项目作者自己。

这意味着产品优先级不是“让很多人快速接入”，而是：

- 服务可靠运行。
- 微信作为首个主要外部设备插件，交互自然。
- 定时任务可信。
- 任务结果可追问。
- 主节点能理解长期上下文，但不会因为长期历史变得越来越慢。
- 能安全地使用本机工具和本机 Codex 登录态。

## 主要场景

### 微信主对话

用户在微信中和助手对话。微信对用户来说就是一个连续助手，不需要知道底层 session、task、run、event。对系统来说，微信只是插件，不是核心架构中心。

### 定时任务

用户可以让助手创建定时任务。定时任务到点后由 scheduler 写入 Event Hub 事件，并由 Supervisor 先感知：简单提醒可以直接走消息插件通知用户，复杂、耗时或带大上下文引用的任务再通过 Worker Group 异步执行。Worker 任务结束后写入结构化 task event，再交给主节点判断是否通知用户。

### 手动复杂任务

用户通过微信或其它输入插件提出复杂问题时，主节点可以启动 Worker Group。任务可以继续、查询、取消，并把结果反馈给主节点。

### 主节点维护

主节点长期使用 Codex session，但每天或达到阈值后生成 handoff summary，并开启新的主 session。

## 非目标

- 不做多用户 RBAC。
- 不做 Web 管理后台作为核心入口。
- 不做插件市场。
- 不追求支持所有 IM 平台，但架构上允许以插件形式接入。
- 不把用户的私人配置、私人任务、私人消息做进开源仓库。
- 不做复杂权限系统。服务默认以用户自己的身份运行。

## 产品取舍

### 统一由主节点发消息

普通业务消息默认由主节点决定发送。这样所有对用户说的话都经过同一个人格、上下文和打扰判断。实际发送由消息插件消费 command 执行。

例外是系统级紧急告警，例如：

- Codex 登录失效。
- 微信发送凭证失效。
- 磁盘空间导致服务无法运行。
- 主节点长期不可用。

这些可以由系统直接发送。

### 不抢占主节点

主节点不做抢占式中断。微信消息优先级最高，但如果主节点正在执行一个 turn，微信消息会进入队列，等待当前 turn 完成后立刻处理。

这个选择避免 AI 执行过程中的副作用回滚问题。
